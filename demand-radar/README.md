# 需求雷达

在你自己的电脑上，按关键词或链接抓小红书、抖音、B站、知乎、微博、贴吧、快手的帖子和评论，也能抓 App Store 评论、GitHub Issues、Hacker News、Reddit、YouTube、X（推特）和任意网页。所有来源合在一起，自动挑出"有没有 app 可以""为什么没人做""谁做我第一个买""is there an app""I'd pay for this"这类需求信号，按热度排好序。

有两种用法：**需求雷达软件**（有窗口，点点鼠标就行，推荐），以及原来的命令行 `radar.sh`。两者的结果放在同一个文件夹里，互相都能看到。

国内平台的抓取用开源项目 [MediaCrawler](https://github.com/NanmiCoder/MediaCrawler)。它用真实 Chrome 浏览器和你自己的登录状态访问页面，许可证只允许学习和个人研究使用，不允许商用。各平台的用户协议大多不欢迎自动采集：只用于自己做研究，每次抓几十条，别开太快。

## 需求雷达软件

| 页面 | 能做什么 |
|---|---|
| 新建采集 | 三种抓法：按关键词搜索、贴链接深挖（帖子评论抓全，或者抓任意网页的正文）、抓某个作者的帖子。平台可以多选，按顺序一个个抓。贴链接会自动认出是哪个平台。常用关键词可以存成"关键词组"，点一下就填进去。 |
| 采集任务 | 排队执行，一次跑一个。每个平台的进度（抓了几条帖子、几条评论）实时更新；等扫码、遇到滑块验证时会提示你去 Chrome 窗口里操作。可以随时停止，已经抓到的照样保存、打分。 |
| 结果 | 跑完自动打分。"需求信号""按帖子汇总""全部数据"三张表，可以按平台、信号类型、点赞数筛选，按任意一列排序，点"打开 ↗"看原帖。"复制给 Claude"把 summary.md 放进剪贴板；"用 Excel 打开"直接打开需求信号.xlsx。 |
| 线索与回复 | 从采集结果里挑出可能需要你产品的人，AI 判断合不合适、照对方原话写好回复；你审核、批准后发出去，对方回了以后标出想试用、问价格的人。详见下面"线索与回复"。 |
| 搜全部数据 | 在所有采集过的帖子和评论里找一句话，比如某个 App 的名字。 |
| 平台与登录 | 每个平台的登录状态和上次成功采集的时间；"重新登录"（换账号、被限制时用）；不用登录的来源可以"检查连接"。 |
| 设置 | 请求间隔、代理、App Store 地区、Reddit 默认版块、小红书排序、默认抓多少、关键词组；抓取用的 Key（GitHub、YouTube、X）；线索与回复（AI、产品介绍、每天上限、发送方式）；发送账号（Reddit、X）。 |

**新加的不用登录的来源：**

| 来源 | 抓什么 | 说明 |
|---|---|---|
| App Store 评论 | 按关键词找 App，抓评分和评论（评论开头标着几星） | 国内直连。苹果的评论接口据报 2026 年 8 月起可能返回空，取不到会自动换网页版接口，两个都不行时日志里会写明。 |
| GitHub Issues | 按 👍 数排的功能请求和抱怨 | 关键词可以用 GitHub 搜索语法，比如 `dark mode label:enhancement`。不填 Token 每小时 60 次。 |
| Hacker News | 帖子和评论，还会直接搜命中关键词的评论 | 需要代理。评论没有公开点赞数。 |
| Reddit | 指定版块里的帖子和评论 | 需要代理。Reddit 自己的接口不登录已经用不了，改走公开存档 Arctic Shift（数据会晚一点）。关键词写成 `r/SaaS alternative to` 只搜那个版块，不写就搜设置里的默认版块。 |
| YouTube | 视频和评论（按相关度） | 需要代理。要在设置里填 YouTube API key：Google Cloud 控制台新建项目 → 启用 YouTube Data API v3 → 凭据 → 创建 API 密钥，免费。免费额度每天大约能搜 100 次（每次搜索 100 点，每天 10000 点），抓评论几乎不占额度。 |
| X（推特） | 最近 7 天的推文和下面的回复 | 需要代理。要在设置里填 X API 的 Bearer Token（developer.x.com 建应用后拿到）。X API 按用量收费，每读一条推文都算钱，所以先少抓一点试试。关键词可以直接写 X 的搜索语法，比如 `"is there an app" lang:en`。 |
| 任意网页 | 贴链接抓正文 | 要登录或全靠脚本渲染的页面抓不到。 |

这几个来源都是按接口文档写的，还没在真实网络上跑过：第一次用之前，先到"平台与登录"点"全部检查一遍"。哪个连不上，把提示发给我。

### 线索与回复

流程：采集 → 导入线索 → AI 判断、写回复 → 你审核 → 发出 → 查回复。

1. **准备（设置 → 线索与回复）：**
   - Anthropic API key：在 console.anthropic.com 申请，按用量付费，大约每判断一条几美分。国内要开代理（在"网络和接口"里填，或用系统代理）。
   - 产品名称、一句话说明（做什么、解决什么问题、给谁用）、产品链接、你的身份（比如"我是 XX 的开发者"）。AI 只按你写的介绍说话，不会编功能。
   - 每天上限：每个平台一个数，你自己定（0–1000，0 = 这个平台不发）。手动发的也算在里面。没有"每天至少发多少"。
   - 发送方式：Reddit 和 X 可以选"批准后用官方接口自动发"或"复制后我自己去发"。其他平台（小红书、抖音、B站、知乎、YouTube……）都是复制后自己去发。
   - 批量发送间隔：两条之间至少隔几秒（还会随机多等一点），默认 90 秒。
   - 自动查回复：每隔几分钟用 Reddit / X 账号查一次谁回复了，0 = 不自动查。
2. **发送账号（设置 → 发送账号）：** 每个平台接一个，就是你自己的账号。
   - Reddit：登录后打开 reddit.com/prefs/apps → 创建应用，类型选 script，回调地址随便填 `http://localhost:8080`；把应用名下面那串（client id）、secret、你的用户名和密码填进来。Reddit 2025 年底起新建 API 应用可能要先申请、审核通过才能用；没批下来就把发送方式选成"复制后我自己去发"。
   - X：在 developer.x.com 建应用 → User authentication settings 里把权限设成 Read and write → Keys and tokens 里生成 API Key / Secret 和 Access Token / Secret（改权限后要重新生成）。X 发帖按用量收费；X 也可能不允许用接口回复没 @ 过你的人，这时那条会显示"发送失败"，点"改为手动发"就行。
   - 填好后点"测试"，能看到账号名就说明通了。
3. **导入线索（线索与回复页 → 找线索）：** 选一次采集，按需求信号得分从高到低导入。会自动跳过：同一个平台上已经导入过的人（一个人只联系一次）、说过别再联系的人、App Store 评论（没法回复）。旧任务没有线索文件时，先在任务页点"重新打分"。
4. **AI 判断：** 只有对方自己说出的需求正好是你的产品解决的，才算合适；广告、段子、已经解决了的、沾边但不对口的、心情不好或话题敏感的，都算不合适。合适的会写一条 2–4 句的回复：先回应对方说的具体情况、给一个有用的建议，再说明你是开发者、介绍一次产品。小红书、抖音、快手、B站、微博上不放链接。
5. **审核和发送：**
   - "待审核"里每条都能直接改；"批准"、"批准并发送"、"跳过"、"不再联系此人"。可以勾选后批量操作，也可以"全部批准并发送"（只发设成自动发的平台，发之前会再确认一次条数、间隔和上限）。
   - 自动发的平台：批准后按间隔一条条发出，到了当天上限就停，剩下的留在"待发送"，第二天再发。
   - 手动发的平台：点"复制并打开"，回复已经复制好、原帖已经打开，贴上发出去，回来点"我已发出"。点过"复制并打开"的那条以后只能手动发，不会再用接口发一遍。
   - 发送时超时、断线、对方服务器出错，或者发送途中软件被关掉：不知道发出去没有，那条会标成"不确定发出去没有"，不会自动重发。去原帖看一眼：看到了点"已经发出去了"，没有点"没发出去"，然后才能再发。
   - 没有你批准，什么都不会发出去。
6. **查回复：** Reddit 和 X 自动查（或点"查回复"）；其他平台对方回复了，把原话贴到那条线索的"记录对方回复"里。AI 会标出意图（想试用、问价格、提问、积极、拒绝、别再联系）；想试用、问价格的标成 🔥 热线索，侧栏会显示数字，还会给一句建议怎么回。对方说不感兴趣或让你别再联系，这个人会自动加进"不再联系"。

线索、回复和不再联系名单都存在 `~/demand-radar/outreach/leads.json`。这个文件要是坏了读不出来，线索功能会先停用（免得忘了联系过谁、再联系一遍），页面上会写明怎么处理。各平台对广告和推销有自己的规定：先少量试，看对方的反应再说。

**打开软件：** 装好以后在启动台里点"需求雷达"，或者在终端运行 `open ~/Applications/需求雷达.app`。软件在一个独立窗口里打开；没装上窗口组件时会在浏览器里打开，功能一样，这时左下角有"关闭需求雷达"。正在采集时关窗口会先问你。

## 安装（macOS）

需要先装好 Google Chrome。其他依赖由脚本自动安装：uv、Python 3.11 以上和 MediaCrawler 的依赖。没有 Node.js 时会用 Homebrew 安装。

```bash
git clone --depth 1 --branch claude/user-demand-research-qzl4la --filter=blob:none --sparse \
  https://github.com/ZRYhandsome/Auto-GPT.git ~/demand-radar-kit
cd ~/demand-radar-kit && git sparse-checkout set demand-radar
bash ~/demand-radar-kit/demand-radar/setup_mac.sh
```

装好后所有东西都在 `~/demand-radar`，"应用程序"里会多一个"需求雷达"，装完会自动打开。脚本可以重复运行，重跑会把 MediaCrawler 和软件都更新到最新版；你的设置、关键词组和采集结果不受影响。

**升级需求雷达：**

```bash
git -C ~/demand-radar-kit pull && bash ~/demand-radar-kit/demand-radar/setup_mac.sh
```

没改过 `keywords.txt` 的话，会顺带换成新版默认关键词；改过就保留你的。

## 命令行用法

```bash
~/demand-radar/radar.sh -p xhs -n 20 -c 10     # 先只试小红书
~/demand-radar/radar.sh                        # 跑全部默认平台
~/demand-radar/radar.sh -p "xhs zhihu" -k "有没有app可以 记账,求推荐 记账软件"
~/demand-radar/radar.sh -p xhs -d "帖子链接1,帖子链接2"   # 深挖：把这几个帖子的评论抓全
~/demand-radar/radar.sh -p xhs -k "桌签,座次表"          # 验证一个具体点子：看 summary.md 的"热度最高的帖子"
~/demand-radar/radar.sh -m ~/demand-radar/runs/20261001-152817   # 不抓取，用新规则重新打分
```

| 参数 | 含义 | 默认 |
|---|---|---|
| `-p` | 平台，空格分隔：xhs 小红书、dy 抖音、ks 快手、bili B站、wb 微博、tieba 贴吧、zhihu 知乎 | `xhs zhihu dy bili wb tieba` |
| `-k` | 关键词，英文逗号分隔；不填就读 `keywords.txt` | 读文件 |
| `-n` | 每个关键词最多抓多少条帖子，小红书最少 20 | 20 |
| `-c` | 每条帖子最多抓多少条一级评论 | 20 |
| `-s` | 同时抓楼中楼回复，会更慢 | 不抓 |
| `-d 链接` | 深挖：不搜索，只抓指定帖子的评论，链接用英文逗号分隔。一次一个平台，每帖默认 300 条一级评论，不抓楼中楼（加 `-s` 才抓；MediaCrawler 会把楼中楼算进 300 条里，一条热门评论的上百条回复会挤掉后面的点子） | |
| `-m 目录` | 不抓取，只对已有结果重新合并打分 | |

**第一次跑某个平台**会弹出一个独立的 Chrome 窗口，用手机上对应的 App 扫码登录。登录状态会保存，下次不用再扫。遇到滑块验证，就在这个窗口里手动拖一下。

**关键词**写在 `~/demand-radar/keywords.txt`，每行一个。越像用户求助、抱怨的原话越好，可以在后面加领域词缩小范围，比如"有没有app可以 记账"。

## 结果

每次运行在 `~/demand-radar/runs/时间戳/` 下生成：

| 文件 | 内容 |
|---|---|
| `需求信号.xlsx` | 两页：“需求信号”和“按帖子汇总”，内容同下面两个 csv |
| `需求信号.csv` | 命中需求信号的帖子和评论，按得分排序，带点赞数、所属帖子、帖子类型和链接 |
| `按帖子汇总.csv` | 每个帖子的评论区命中了多少条需求、多少人求安卓或鸿蒙版、代表评论 |
| `全部数据.csv` | 所有抓到的帖子和评论 |
| `summary.md` | 各平台和各搜索词的命中情况、得分最高的 50 条、热度最高的帖子（含求模板和口令评论数）、评论区需求最多的帖子、值得深挖的帖子和深挖命令，最后附上全部命中的原文（按帖子分组） |
| `signals.jsonl` | 和需求信号.csv 同样的行，多了作者，给"线索与回复"导入用 |
| `crawl.log` | 抓取日志，出错时看这里 |

**打分方式：**

1. **认帖子类型。** 标题在问“你想要什么 app”“为什么没人做”“来许愿你的理想 APP”的是征集需求帖，在找工具或找人开发的是求助帖，开发者介绍自己产品的是推广帖，其余算其他。
2. **认信号。** 每条文字看命中了哪些信号，各有权重：付费意愿 4，求工具、缺失 3，抱怨现有、想要、求其他平台、找人开发、回应征集、求模板 2，改进建议、痛点、附和 1。征集帖下的一级评论哪怕只写了一个点子，比如“记录梦境！”，也记一个“回应征集”。楼中楼回复（多是在评论别人的点子，比如“没盈利没人搞的”）、“发现宝藏”这类叫好、推荐现成产品的不算回应征集。引流、接单、发邀请码、开发者推广自己产品的评论完全不计分。
3. **热度为主，措辞为辅。** 点赞和回复代表有多少人跟着说，取对数放大：1 万赞只比 10 赞高几倍，不会高一千倍。信号分先开平方再相乘，命中的信号多往往只是话说得长，不该压过点赞：208 赞的“滴滴拉屎”要排在 2 赞的长评论前面。
4. **按帖子类型加权。** 推广帖本身只算一成分，它的评论区算七成：那里多是对某个现成产品的反馈，比如“蹲安卓”。征集帖下的评论加两成；泛泛地问“大家想要什么”的征集帖本身只算三成，它只是来源，点子在评论区。带 [doge] 的玩笑话打六折。

这一步只做初筛。把 `summary.md` 发给 Claude（在 Mac 上跑完会自动复制到剪贴板，直接粘贴即可），可以继续聚类，并核实这些需求是不是已经有人做好了。不用发终端日志：日志被截短了，点赞数看不到。

**深挖：** 搜索模式每帖只抓前 20 条评论，像“明明很需要的 APP 功能，为什么就是没有人做？”这种两千条评论的帖子，大部分点子都没抓到。`summary.md` 的“值得深挖的帖子”一节会列出这类帖子，并给出现成的深挖命令，复制运行即可。已经深挖过的帖子不会再出现在这里。

## 常见问题

- **一直要扫码或提示登录失败：** 在弹出的窗口里手动完成验证后重跑。软件里到"平台与登录"点"重新登录"；命令行用户删掉 `~/demand-radar/MediaCrawler/browser_data/` 下对应平台的文件夹。
- **软件打不开、窗口一闪就没：** 看 `~/demand-radar/app.log` 的最后几行；也可以在终端运行 `cd ~/demand-radar/app && ../MediaCrawler/.venv/bin/python server.py` 直接看报错。
- **Reddit、Hacker News、YouTube、X 连不上：** 国内要开代理。软件默认用系统代理；代理软件没有设成系统代理时，在"设置 → 代理"里填地址，比如 `http://127.0.0.1:7890`。
- **报错 `Page.goto: Timeout 30000ms exceeded`（打开首页超时）：** 网络慢，或首页有资源一直加载不完。新版最多等 90 秒，页面已经打开就继续跑。还是失败的话，直接重跑同一条命令。
- **日志里有 `--- Logging error ---`：** 旧版的问题，不影响抓取。MediaCrawler 会把整页搜索结果写进日志，一行几十 KB，经 `tee` 写日志时会失败。新版把每条日志截到 300 字，数据照常完整写进 jsonl。要看完整日志就设置 `RADAR_LOG_FULL=1`。
- **小红书搜索排序：** 默认用综合排序。MediaCrawler 原本按最热排序，搜出来多是高赞的推广帖和段子。想换回去就设置 `RADAR_XHS_SORT=popularity_descending`，按最新排序用 `time_descending`。
- **任务显示"没抓完"，或者报 `tenacity.RetryError ... raised KeyError`：** 小红书（或别的平台）中途拦住了请求，多半是一次抓得太多、太快，触发了验证或限流。新版遇到这种情况会停手，已经抓到的都保存、打分，并写明哪些关键词没抓完；过半小时到一小时，在任务页点"接着抓剩下的 N 个关键词"。不容易被拦的抓法：每帖评论 50 条以内，关键词多就分几次抓，请求间隔调到 5 秒左右。某一条帖子出错只会跳过这一条，不会让整次采集停下。
- **被限流或封号：** 用小号登录；把 `-n` 和 `-c` 调小；加长间隔，例如 `RADAR_SLEEP_SEC=5 ~/demand-radar/radar.sh`。
- **依赖安装很慢或失败：** MediaCrawler 默认用清华镜像，脚本连不上时会自动改用官方 PyPI。
- **想用日常 Chrome 的登录状态：** 按 MediaCrawler 文档给日常 Chrome 开启远程调试，再运行 `RADAR_CONNECT_EXISTING=1 ~/demand-radar/radar.sh`。
- **用 Edge 或 Chrome 不在默认位置：** 设置 `RADAR_BROWSER_PATH=浏览器可执行文件路径`。
- **某个平台失败：** 脚本会跳过它继续跑别的平台，最后告诉你哪些失败了。单独重跑即可，例如 `radar.sh -p dy`。

## 文件

| 文件 | 作用 |
|---|---|
| `setup_mac.sh` | 一键安装 |
| `radar.sh` | 批量运行多个平台，然后合并打分 |
| `run_mc.py` | MediaCrawler 启动包装：自己开独立浏览器窗口、小红书用综合排序、截短日志、打开网页多等一会儿、一条请求失败不拖垮整次采集，不改 MediaCrawler 源码 |
| `merge.py` | 合并各平台 jsonl 结果、识别中英文需求信号、打分并输出表格 |
| `app/server.py` | 需求雷达软件：只在本机运行的小服务（只用 Python 标准库），加网页界面 `app/web/`；有 pywebview 时用独立窗口 |
| `app/jobs.py` | 采集任务：排队、逐个平台运行、进度和日志、停止、跑完自动打分；也列出命令行跑出来的结果 |
| `app/outreach/` | 线索与回复：线索存储（`store.py`）、调用 Claude 判断和写回复（`agent.py`）、Reddit / X 官方接口发送和查回复（`senders.py`）、导入、判断、发送、查回复的后台任务和每日上限（`manager.py`） |
| `app/sources/` | 不用登录的来源（App Store、GitHub、Hacker News、Reddit、YouTube、X、任意网页），写出和 MediaCrawler 一样格式的 jsonl |
| `app/run_source.py` | 运行一个不用登录的来源，参数和 MediaCrawler 一样 |
| `keywords.txt` | 默认关键词 |
| `tests/test_merge.py` | 用模拟的 7 个平台数据和真实跑出来的误报、漏报测试 merge.py |
| `tests/test_sources.py` | YouTube、X 数据源、作者字段和 signals.jsonl 的测试 |
| `tests/test_outreach.py` | 线索与回复的测试：用假的 Claude 客户端和假的 Reddit / X 接口，不联网 |
| `tests/test_run_mc.py` | 用假的 MediaCrawler 测包装脚本：一条帖子出错只跳过这条，被平台拦住时停手、保存、报出没抓完的关键词 |
| `tests/test_app.py` | 软件的测试：各来源的解析（录好的接口数据）、用假的 MediaCrawler 跑完整任务、停止、本机服务接口和安全检查。全部测试：`python3 -m unittest discover tests` |
